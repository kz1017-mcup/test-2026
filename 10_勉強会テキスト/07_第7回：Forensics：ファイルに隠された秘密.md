# 📂 第7回：Forensics：ファイルに隠された秘密

今回は「Forensics（デジタル・フォレンジック）」に挑戦します。一言でいうと、**「渡されたファイルを徹底的に調べ上げ、中に隠された情報を暴き出す」** ジャンルです。

第6回のOSINTでは「画像から場所や人物を読み解く観察力」を鍛えましたが、今回はその観察力を**ファイルそのもの**に向けます。見た目は普通の画像やテキストファイルでも、中身をひっくり返してみると、まったく別のデータが隠れていることがあります。

#### 🔍 Forensicsの合言葉：「まずは正体を疑う」

Forensicsに限らず、CTF全体を通して使える大原則があります。

> **「正体不明のファイルを渡されたら、まずそのファイルが"本当は何なのか"を疑ってみる」**

拡張子や見た目を鵜呑みにせず、「本当にこのファイルはこの形式なのか？」「この中に、もう1つ別のデータが紛れ込んでいないか？」と疑うところから、Forensicsの調査は始まります。今回の3問を通して、この視点を体に染み込ませていきましょう。

## 📝 第1問：Flag in Flame (picoMini by CMU-Africa - Easy)

### 1. 前提知識：「怪しいテキストの塊」を見つけたら疑うこと

#### 📄 ログファイルの皮を被った「何か」

大量のテキストが並んだファイルを渡されたとき、いきなり全部読もうとするのは非効率です。まずは**「様子がおかしい部分」がないかをざっと眺める**のがコツです。

たとえば、以下のような特徴に気づけたら要注意です。

* 改行がほとんどなく、**やたら長い1行**が延々と続いている
* 使われている文字が **`A-Z` `a-z` `0-9` `+` `/` `=`** だけに偏っている

これは第4回で学んだ **Base64エンコード** の特徴そのものです。「読めない長い文字列＝何かの形式でエンコードされたデータ」という視点は、Forensicsでも変わらず武器になります。

#### 🛠️ CyberChefの「Extract Base64」と「Render Image」

CyberChefには、今回のようにテキストの中に埋め込まれたBase64データを自動で見つけ出す **「Extract Base64」** というレシピや、デコードした結果が画像データであれば、その場で画像として表示してくれる **「Render Image」** というレシピがあります。「怪しいテキスト」を見つけたら、これらのレシピをとりあえず試してみるのがおすすめです。

---

### 2. 問題文

<https://learn.cylabacademy.org/library/523>

> **【問題】 Flag in Flame**
> SOCチームが、侵害を受けたサーバーで異常に大きなログファイルを発見しました。しかし開いてみると、typicalなログではなく巨大な1つのエンコード済みテキストの塊でした。何か隠れていないか調査し、本当の目的を明らかにしてください。

### 3. ヒント

* ダウンロードした`logs.txt`を開いてみましょう。改行がほとんど無い、非常に長い1行になっていませんか？
* 使われている文字の種類に注目してください。Base64の特徴（`A-Z a-z 0-9 + /`、末尾に`=`）に当てはまりませんか？
* CyberChefの「From Base64」でデコードした結果を、そのまま画像として表示する方法（Render Image）があります。

### 4. 詳細な解説（解き方）

#### 🛠️ ステップ1：ファイルの中身を確認する

配布された`logs.txt`をテキストエディタで開くと、改行がまったくない、非常に長い1行の文字列だけが書かれています。中身は`A-Z a-z 0-9 + /`のみで構成されており、Base64エンコードされたデータそのものだと推測できます。

#### 🛠️ ステップ2：CyberChefでデコード＆画像化する

1. **[CyberChef](https://gchq.github.io/CyberChef/)** を開き、Input欄に`logs.txt`の中身をまるごと貼り付けます。
2. Operationsから **「From Base64」** をRecipeに追加します。
3. 続けて **「Render Image」** をRecipeに追加します。
4. Output（またはプレビュー）に、フードを被った人物のイラストが表示されます！

#### 🛠️ ステップ3：画像の中の文字列を読み取る

表示された画像の下部に、16進数（Hex）の文字列がびっしりと書き込まれています。この文字列をコピーし、CyberChefのRecipeを **「From Hex」** に入れ替えてデコードすると、フラグが姿を現します。

#### 🎯 答え合わせ

**Flag:** `picoCTF{forensics_analysis_is_amazing_ec1984fc}`

「ただの長いテキスト」だと思って読み飛ばしていたら、その中に画像が丸ごと1つ隠れていました。「怪しい文字列は、まずBase64を疑ってCyberChefに突っ込んでみる」——これだけで一気に世界が変わることを体感できたと思います。

> 💡 **実務に繋がるポイント：「地味なファイル」に紛れ込ませる攻撃者の心理**
> 攻撃者やマルウェアは、盗み出したデータや不正な命令を、あえて「一見退屈でボリュームの大きいファイル」（今回のような巨大ログ、設定ファイル、バックアップファイルなど）に埋め込むことがあります。SOC（セキュリティ監視センター）のアナリストは日々大量のログを監視していますが、すべてを1行ずつ目視することは不可能です。「量が多い」「地味に見える」という理由で見過ごされがちなファイルこそ実は一番怪しい——これは実際のインシデント対応でも通用する感覚です。

## 📝 第2問：Corrupted file (picoMini by CMU-Africa - Easy)

### 1. 前提知識：ファイルの正体は「先頭のバイト」が決めている

#### 🏷️ マジックバイト（ファイルシグネチャ）とは？

拡張子（`.jpg`や`.pdf`など）は、実はファイルの中身を保証するものではありません。OSやソフトが「このファイルは本当は何者か」を判断する手がかりは、**ファイルの先頭数バイトに書き込まれた決まった合言葉（マジックバイト / シグネチャ）** です。

| ファイル形式 | 先頭のマジックバイト（16進数） |
| --- | --- |
| JPEG画像 | `FF D8 FF` |
| PNG画像 | `89 50 4E 47`（`.PNG`） |
| PDF | `25 50 44 46`（`%PDF`） |
| ZIP | `50 4B 03 04`（`PK..`） |

もしこの先頭バイトが壊れていたり、別の値に書き換えられていたりすると、中身は無事でも**OSやビューアーが「壊れたファイル」「開けないファイル」と判断してしまいます**。逆に言えば、正しいマジックバイトに書き戻すだけで、ファイルは何事もなかったかのように復活します。

#### 🛠️ ブラウザで使えるHexエディタ「HexEd.it」

ファイルの中身をバイト単位（16進数）で直接見たり、書き換えたりできるツールを**Hexエディタ**と呼びます。**[HexEd.it](https://hexed.it/)** はインストール不要でブラウザ上にそのまま動く無料のHexエディタで、ファイルをドラッグ＆ドロップして開き、値を書き換えて、そのまま新しいファイルとして保存できます。

---

### 2. 問題文

<https://learn.cylabacademy.org/library/519>

> **【問題】 Corrupted file**
> このファイルは壊れているように見えます……本当にそうでしょうか？数バイトを直すだけで元通りになるかもしれません。

---

### 3. ヒント

* HexEd.itでファイルを開き、**一番先頭の数バイト**を確認してみましょう。
* ファイルの少し後ろの方に`JFIF`という文字列が見えませんか？これはある画像形式の目印です。
* その画像形式の正しい先頭バイトが何か、調べてみましょう。

---

### 4. 詳細な解説（解き方）

#### 🛠️ ステップ1：HexEd.itでファイルを開く

配布されたファイルを[HexEd.it](https://hexed.it/)にドラッグ＆ドロップして開きます。先頭のバイト列を確認すると、以下のようになっています。

```
5C 78 FF E0 00 10 4A 46 49 46 00 01 ...
                  (J  F  I  F)
```

`JFIF`という文字列（JPEGファイルの目印）が途中に見えるのに、正しいJPEGの先頭バイトである`FF D8 FF`にはなっていません。**先頭2バイトが`5C 78`という余計な値に書き換えられている**ことが分かります。

#### 🛠️ ステップ2：正しいマジックバイトに書き換える

HexEd.it上で先頭2バイトをダブルクリックし、`5C 78` を正しいJPEGの先頭バイト **`FF D8`** に書き換えます。

#### 🛠️ ステップ3：ファイルとして保存し、開く

「名前を付けて保存」で`.jpg`拡張子を付けて保存し、画像ビューアーで開きます。今度はきちんと画像として表示され、そこにフラグがそのまま書かれています。

#### 🎯 答え合わせ

**Flag:** `picoCTF{r3st0r1ng_th3_by73s_efd8c6c0}`

たった2バイトを書き換えるだけで、「壊れたファイル」が「開けるファイル」に早変わりしました。ファイルの正体は拡張子ではなく中身のバイト列が決めている、ということがよく分かる一問です。

> 💡 **実務に繋がるポイント：**
> ファイルアップロード機能を持つWebサービスの中には、「拡張子だけ」をチェックして安全性を判断してしまっているものがあります。今回学んだ「マジックバイトは書き換えられる」という事実は、そうしたチェックがすり抜けられてしまう危険性そのものです。実際のWebサイト診断（ペネトレーションテスト）でも、正しい画像のマジックバイトを持たせつつ中身に不正なプログラムを仕込んだ「偽装ファイル」をアップロードし、拡張子・マジックバイトだけしかチェックしていないサーバーを突破する、という手法が実際に使われています。

## 📝 第3問：Hidden in plainsight (picoMini by CMU-Africa - Easy)

### 1. 前提知識：画像に別のデータを隠す「ステガノグラフィ」

#### 🖼️ 見た目は変わらないのに、中身は別物

**ステガノグラフィ（Steganography）** とは、「データの存在自体を隠す」技術のことです。暗号化が「読めなくする」技術なのに対し、ステガノグラフィは**「そこにデータがあることにすら気づかせない」**ことを目指します。画像ファイルの中に、見た目を全く変えずに別のファイルやテキストを埋め込む、というのが定番の手口です。

有名なツールに **steghide** があります。パスワード（パスフレーズ）を使って、画像ファイルの中に別のファイルを埋め込んだり、取り出したりできる無料ツールです。

#### 🛠️ 一括で調べてくれる「Aperi'Solve」

ステガノグラフィが疑われる画像を渡されたとき、「どの手法で隠されているか」を1つずつ手作業で試すのは大変です。**[Aperi'Solve](https://www.aperisolve.com/)** は、画像をアップロードするだけで、steghide・binwalk・exiftool・strings・各種ビット分解など、**複数の解析ツールをまとめて自動実行**してくれる非常に便利なサイトです。steghideにパスワードが必要な場合は、専用の入力欄にパスワードを入れておけば、そのまま抽出まで試みてくれます。

---

### 2. 問題文

<https://learn.cylabacademy.org/library/524>

> **【問題】 Hidden in plainsight**
> 一見普通のJPG画像が渡されます。ファイルの中には、目に見えない場所に何かが隠されています。隠されたペイロードを見つけ出し、フラグを抽出してください。

---

### 3. ヒント

* 画像ファイルのメタデータ（コメント欄）を覗いてみましょう。何か意味ありげな文字列が書き込まれていませんか？
* その文字列はBase64のようです。CyberChefでデコードしてみましょう。
* デコードした結果に、さらに`:`で区切られた別のBase64文字列が含まれていませんか？
* 最終的に得られる文字列は、あるステガノグラフィツールの「合言葉（パスワード）」かもしれません。

---

### 4. 詳細な解説（解き方）

#### 🛠️ ステップ1：画像のメタデータを確認する

配布された画像をJimpl（第6回で使ったメタデータ確認サイト）や[Aperi'Solve](https://www.aperisolve.com/)にアップロードすると、**Comment（コメント）欄**に以下のような文字列が埋め込まれていることが分かります。

```
c3RlZ2hpZGU6Y0VGNmVuZHZjbVE9
```

#### 🛠️ ステップ2：二重にBase64デコードする

CyberChefで「From Base64」を使ってこの文字列をデコードすると、次の文字列が出てきます。

```
steghide:cEF6endvcmQ=
```

`steghide`という単語と`:`の後ろにまだBase64らしき文字列が続いています。もう一段、`cEF6endvcmQ=`だけを「From Base64」でデコードすると……

```
pAzzword
```

**steghideのパスワードそのもの**が姿を現しました。

#### 🛠️ ステップ3：Aperi'Solveでsteghideによる抽出を実行する

1. [Aperi'Solve](https://www.aperisolve.com/)に画像をアップロードします。
2. **Password欄** に、先ほど見つけた `pAzzword` を入力して解析を実行します。
3. 結果一覧の **「Steghide」** の項目が成功（Success）となり、`flag.txt`が抽出されたことが分かります。
4. 「Download file」から抽出結果をダウンロードして開くと、フラグが書かれています。

#### 🎯 答え合わせ

**Flag:** `picoCTF{h1dd3n_1n_1m4g3_e7f5b969}`

画像のメタデータに残っていた、一見無意味な文字列を二重にデコードしたら、まさかの「別ツールのパスワード」でした。「1つの手がかりが、次の手がかりへの鍵になる」という、Forensicsならではの連鎖を体験できたと思います。

> 💡 **実務に繋がるポイント：ステガノグラフィは"読み物"ではなく実際に使われている**
> 画像に情報を隠す技術は、CTFだけのお遊びではありません。実在のマルウェア・APT攻撃グループの中には、**画像ファイルの中に遠隔操作サーバーのアドレスや追加の攻撃コードを埋め込み、SNSや正規のWebサイトから画像をダウンロードさせることで、ネットワーク監視をすり抜けて指令を受け取る**という手口を使うものが確認されています。また、社内の機密情報を画像ファイルに隠し、メールの添付ファイルとして持ち出す「情報漏えい」の手口として悪用されることもあります。ファイルの中身をチェックする仕組み（DLP：情報漏えい対策製品）が、拡張子や見た目だけでなく、こうした「隠れた中身」まで見抜けるかどうかが問われています。

## 📅 第7回のまとめ

今回はForensicsの基本となる3つの考え方を体験しました。

* **怪しいテキストの塊は、まずBase64を疑う**：CyberChefの「Extract Base64」「Render Image」で一気に正体を暴ける
* **ファイルの正体は拡張子ではなくマジックバイトが決める**：Hexエディタで先頭バイトを直すだけで「壊れたファイル」が復活する
* **ステガノグラフィは、見た目を変えずにデータを隠す技術**：Aperi'Solveのような統合解析ツールで、複数の手法をまとめて疑ってみる

3問とも「①ブラウザ上のツールにファイルを読み込ませる」「②出てきたヒントを次のツールに渡す」という操作の繰り返しでした。1つのツールだけで完結する問題はほとんどなく、**複数のツールをリレーのように繋いでいく**のがForensicsの醍醐味です。

### 8. 【本格派向け】Invisible WORDs

<https://learn.cylabacademy.org/library/354>

* **概要:** 一見普通のAI生成画像から、フラグを見つけ出す問題（picoCTF 2023 / 難易度Hard・正答率58%）。
* **ポイント:** 実は文字コードのUnicode（世界中の文字を扱う仕組み）には、**画面には一切表示されない「幅ゼロの文字」（ゼロ幅スペース U+200B など）** が存在し、これを普通の文章の隙間に埋め込むことで、見た目を一切変えずにテキストを隠すことができます。この技術は、AIチャットサービスへの「見えない命令の埋め込み（プロンプトインジェクション）」対策の文脈でも近年注目されています。[Unicode Steganography](https://330k.github.io/misc_tools/unicode_steganography.html)のようなブラウザ上で動く無料ツールで、実際に文字を隠す／取り出す体験ができます。他の問題よりかなり難易度が高いので、じっくり時間をかけて挑戦したい方向けです。
