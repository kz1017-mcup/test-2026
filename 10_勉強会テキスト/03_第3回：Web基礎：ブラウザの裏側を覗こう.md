# 🌐 第3回：Web基礎：ブラウザの裏側を覗こう

今回はCTFの王道ジャンル **「Web」** の攻略です！
私たちが普段見ているWebサイトは、さまざまな仕組みが組み合わされて作られているものです。
今回は、このWebサイトの仕組み（HTML、Javascript、CSS、Cookieなど）に簡単に触れ、Webサイトがどのような仕組みで動いていて、どういった部分にハッカーに攻撃されるスキが生まれるかを学んでみましょう。
ブラウザの強力な機能 **「開発者ツール（F12）」** を使うと、Webの裏側がどうなっているのか簡単にわかります。

今回は、初心者向けCTFの定番サイト **picoCTF** の実問題を使い、3つのステップでWeb解析の基礎を学びます。

---

## 📝 第1問：Inspector (picoCTF - Easy)

### 1. 前提知識：Webページの仕組みと「開発者ツール」

#### 🌐 Webページは何でできている？（3つの要素）

私たちが普段スマホやPCで見ているすべてのWebサイトは、主に3つの言語（ファイル）が組み合わさって動いています。家づくりに例えると非常にイメージしやすくなります。

```
  【HTML】            【CSS】             【JavaScript】
  [骨組み・構造]  ＋   [装飾・デザイン]  ＋  [仕掛け・動き]   ＝  完成したWebサイト！

```

* **① HTML（エイチ・ティー・エム・エル）：【家の「骨組み」】**
* ページの文字、画像、リンクなどの「配置」を決める構造です。
* 画面上には見えない「開発者用のメモ（コメント）」を残す機能があり、CTFではここにフラグが置き忘れられているのが超定番です。


* **② CSS（シー・エス・エス）：【家の「インテリア・壁紙」】**
* 文字の色、大きさ、背景、配置のレイアウトなど「デザイン」を担当します。


* **③ JavaScript（ジャバスクリプト）：【家の「自動ドアや家電の仕掛け」】**
* ボタンを押したときにポップアップを出したり、画面を切り替えたりする「動き」を担当します。



---

#### 🛠️ 最強の武器「開発者ツール」とは？

ブラウザ（Google Chrome や Microsoft Edge など）には、Webサイトの裏側（生のコードや通信状態）を監視・分析するための機能「開発者ツール（デベロッパーツール）」が最初から標準で搭載されています。

普段は隠れていますが、以下の操作で一瞬で起動できます。

##### 起動方法

* **Windows:** キーボードの一番上の列にある **`F12`** キーを押す（または `Ctrl` + `Shift` + `I`）
* **Mac:** **`Cmd`** + **`Option`** + **`I`** を同時に押す
* **共通（マウス操作）:** ページ上の何もないところで「右クリック」 ➡ **「検証」** を選択

##### 開発者ツールの主要な「タブ」

開発者ツールが開くと、画面の右側（または下側）に英語だらけの画面が出てきます。最初は焦らなくて大丈夫です！使うタブは決まっています。

| タブの名前 | 何ができる場所？ | CTFでの使いどころ |
| --- | --- | --- |
| **Elements**（要素） | ブラウザが今読み込んでいる**HTMLコード**をリアルタイムで表示する場所。 | コメントアウト（隠しメッセージ）を探すときに使う。 |
| **Sources**（ソース） | サイトで使われている**全ファイル（HTML, CSS, JSなど）**を一覧で確認・閲覧できる場所。 | 外部のCSSファイルやJavaScriptファイルをじっくり読みたいときに使う。 |

---

#### 💡 クイズ：ソースコードの「コメント」ってどう見える？

プログラマーは、コードの中に自分やチーム向けのアドバイスやメモを残すために「コメント」という機能を使います。コメントに書かれた文字は、**ブラウザの画面上には絶対に表示されません**。

しかし、開発者ツールを使うと以下のように丸見えになります。

* **HTMLのコメント:** `<!-- ここにメモを書く -->` （緑色や灰色で表示されることが多い）
* **CSSやJSのコメント:** `/* ここにメモを書く */` や `// ここにメモを書く`

CTFの初心者問題では、「画面には何もないけれど、開発者ツールでHTMLやCSSのコメントを覗くとフラグが書いてある」という問題がよく出題されます。まずは「F12を押して中身を見る」癖をつけましょう！

### 4. 詳細な解説（解き方）

#### ステップ1：HTMLをチェックする

1. Webページを開き、**`F12`** キーを押して開発者ツールを開きます。
2. 「**Elements**（要素）」タブを開き、HTMLコードを確認します。
3. コード内をスクロール（または `Ctrl + F` で `picoCTF` を検索）していくと、HTMLコメント `<!-- ... -->` の中にフラグの1つ目のパーツを発見できます！
> `picoCTF{1ns3pt10n_`



#### ステップ2：CSSファイルをチェックする

1. 「**Sources**（ソース）」タブ（またはHTML内の `<link>` タグのURL）を開きます。
2. デザインを担当している **`mystyle.css`** というファイルを選択します。
3. CSSコードのコメント `/* ... */` の中に、フラグの2つ目のパーツを発見できます！
> `0ut_0f_s1gh7_`



#### ステップ3：JavaScriptファイルをチェックする

1. 同じく「Sources」タブから、プログラムを担当している **`myjs.js`** というファイルを選択します。
2. JSコードのコメントの中に、最後のパーツを発見できます！
> `f723e262}`



#### 🎯 答え合わせ

3つのパーツをガッチャンコすると、フラグが完成します！
**Flag:** `picoCTF{1ns3pt10n_0ut_0f_s1gh7_f723e262}`

## 📝 第2問：dont-use-client-side (picoCTF - Easy)

### 1. 前提知識：JavaScript（ジャバスクリプト）ってなに？

#### 💡 JavaScriptは「Webサイトに動きをつける魔法使い」

第1問で、Webサイトは3つの要素でできているとお伝えしました。

* **HTML:** 家の「骨組み・構造」（文字や写真）
* **CSS:** 家の「壁紙・インテリア」（デザインや色）
* **JavaScript:** 家の「自動ドア・家電・からくり」（**動きや仕組み**）

HTMLとCSSだけだと、Webサイトは「ただ読むだけのポスター」のような静かなページです。そこに「ボタンを押したらポップアップが出る」「入力フォームの文字数を自動でカウントする」「アニメーションを動かす」**といった**「動き」や「計算」を付け加えるのがJavaScript（JS）です。

現在のほぼすべてのWebサイトやWebアプリで、このJavaScriptが使われています。

---

#### 🖥️ JavaScriptは「どこで」動いている？

ここが今回の最も重要なポイントです！

プログラミング言語の中には、Webサイトの管理用コンピュータ（サーバー）の中で動くものもたくさんありますが、**JavaScriptは基本的に「あなたのパソコン（ブラウザ）」の上で動きます。**

つまり、あなたがWebサイトを開いた瞬間、そのページを動かすためのJavaScriptのプログラムが**ネット経由であなたのPCの中に丸ごとダウンロードされ、手元で実行されている**のです。

```
【Webサイトのサーバー】
        │
        │ (JavaScriptのプログラムを送信)
        ▼
【あなたのパソコン（ブラウザ）】
  ➡ 手元にプログラムが到着！
  ➡ あなたのPCの中でJavaScriptが実行される！
  ➡ 第1問で学んだ「F12（開発者ツール）」を使えば、手元にあるプログラムの中身が丸見え！

```

---

#### 🔍 プログラムを解読するための「2つのヒント」

第2問で登場するJavaScriptのコードを読むために、プログラミングを知らなくても分かる「2つのルール」だけ覚えておきましょう！

##### ① `if`（もし〜なら）

プログラムが何かをチェック（判定）するときに書く言葉です。

* 例：`if (入力した文字 == '秘密の言葉')` ➡ 「もし入力した文字が『秘密の言葉』と一緒なら」という意味になります。

##### ② `substring`（文字を切り取る命令）

長い文字列の一部を「〇文字目〜〇文字目」と指定して切り抜く命令です。

* **ポイント：** プログラミングの世界では、文字の数は「1文字目」ではなく「0文字目」から数えます！
* 例：`'picoCTF'.substring(0, 4)` ➡ 0文字目から4文字目の直前まで切り取る ➡ **`pico`**

今回の問題では、パスワードのチェックが数文字ずつバラバラに切られて判定されています。コードを解読してパズルのように組み立て直しましょう！

---

#### ⚠️ コラム：クライアントサイド（手元）で認証をする危険性

セキュリティの基本的なルールとして、「ユーザーの手元（クライアントサイド）に渡るデータやプログラムは、すべて悪意あるユーザーに書き換えられたり覗かれたりする前提で設計しなければならない」という原則があります。

パスワードの正解判定や大切なデータの処理をJavaScript（ブラウザ上）だけで行なってしまうと、今回のように「開発者ツールでコードを開くだけで正解がバレる」という致命的な脆弱性につながります。

本来、ログインなどの重要な認証処理は、ユーザーから中身が見えない「サーバー側（ネットの向こう側）」で行うのが鉄則です！

## 📝 第3問：Cookies (picoCTF - Medium)

### 1. 前提知識：Cookie（クッキー）の仕組みと書き換え

#### 🍪 そもそも「Cookie（クッキー）」ってなに？

Webサイトを見ているとき、ログインしたはずなのにページを移動するたびに「ログインしてください」と聞かれたら不便ですよね。

実は、Webの基本的な通信（HTTP通信）には「前のやり取りを覚えておく機能（記憶力）」がありません。一回一回のページ移動が「はじめまして」の状態になってしまうのです。

この問題を解決するために作られた仕組みが **Cookie（クッキー）** です。

わかりやすく例えると、「テーマパークの再入場スタンプ（手に押すスタンプ）」のようなものです。

```
1. 最初にWebサイトにアクセス（またはログイン）する
2. サイト側が「あなたのブラウザ」に小さなメモ（Cookie）を渡して保存させる
   例: 「この人は ユーザーID: 123 です」
3. 次から別のページを開くたび、ブラウザが自動的にそのメモ（Cookie）を見せる
4. サイト側は「あ、さっきの ユーザーID: 123 さんね！」と記憶してスムーズにページを見せてくれる

```

---

#### 🛠️ 最強の武器「F12」でCookieを覗いてみよう！

このCookieというデータは、**あなたのパソコン（ブラウザ）の中に保存されています**。
ということは……もうお分かりですね！第1問・第2問と同じく、開発者ツール（F12）を使えば**自分のパソコンに保存されているCookieの中身をいつでも見て、自由に書き換えることができます**。

##### Cookieの確認・書き換え手順（Chrome / Edge）

1. キーボードの **`F12`** キーを押して開発者ツールを開きます。
2. 上のタブから **「Application（アプリケーション）」** を選びます。
（※画面が狭くて見当たらない場合は、右端の `>>` マークの中に隠れています）
3. 左側のメニューから **「Storage」 ＞ 「Cookies」** をクリックし、表示されたサイトのURLを選びます。
4. **「Name（名前）」** と **「Value（値）」** が並んだ表が表示されます。この「Value」の部分は、**ダブルクリックすることで好きな数字や文字に書き換えることができます！**

---

#### 🔍 なぜCookieを書き換えると危険なの？

Webサイトを開発するとき、プログラマーがやってしまいがちな「大失敗」があります。それは「Cookieの値をそのまま信用してしまうこと」です。

例えば、以下のようにCookieでユーザーを管理していたとします。

* あなたのCookie ➡ `user_id = 10` （一般ユーザー）
* 管理者のCookie ➡ `user_id = 1` （管理者 / admin）

もしWebサイト側が「Cookieの値をチェックせずにそのまま受け入れてしまう仕組み」になっていた場合、あなたが開発者ツール（F12）で自分のCookieの値を `10` から **`1`** に書き換えてページを再読み込み（リロード）するだけで、**Webサイト側は「あ！管理者様がアクセスしてきた！」と勘違いし、管理者専用ページや機密データ（フラグ）を見せてしまう**のです。

> 実際のWebサイトは、そういったことが起きないように対策がされています。たとえば、訪問者を特定するためには、セッションIDなどの仕組みを使って、ユーザIDを使うことなく特定する仕組みになっているので、ユーザが簡単にほかの訪問者に成りすますことができないようになっています。
---

#### 🎯 第3問のミッション

第3問のWebサイトは、入力したクッキー（お菓子）の名前によって、ブラウザに保存されるCookieの数字（`name = 0` など）が変わる仕組みになっています。

1. **`F12`** を開いて「Application」タブで現在のCookieの値を確認する。
2. Cookieの値（数字）を自分の手で **`1`**, **`2`**, **`3`**... と書き換えてページをリロードしてみる。
3. Webサイトをうまく騙して、秘密のページ（フラグ）にたどり着く！

「手元のデータを書き換えてサイトの反応を見る」という、Web CTFの醍醐味をぜひ体感してみてください！

### 4. 詳細な解説（解き方）

#### ステップ1：初期状態のCookieを確認する

1. サイトの検索窓に、画面の例にある「`snickerdoodle`」と入力して送信します。
2. **`F12`** を押して開発者ツールを開き、「**Application**」タブを選択します。
3. 左メニューの「**Cookies**」から該当のサイトURLをクリックします。
4. 表の中に `name` という名前のCookieがあり、Value（値）が **`0`** になっていることを確認できます。

#### ステップ2：Cookieを書き換えて実験する

1. Cookieの `0` という数字をダブルクリックして、**`1`** に書き換えます。
2. ページをリロード（`F5` または `Ctrl + R`）します。
3. 画面上の文字が別のクッキーの名前（`chocolate chip` など）に変わりました！
4. つまり、このWebサイトは **`name` の数字（0, 1, 2, 3...）によって表示するページ（アクセス権限）を切り替えている** ことが分かります。

#### ステップ3：正解の数字を探す

1. Cookieの値を `2`, `3`, `4`... と順番に書き換えてページをリロードしていきます。
2. **`18`** に書き換えてリロードすると、画面上にスペシャルなメッセージと共にフラグが表示されます！

> 💡 **自動化のココがCTFっぽい！**
> 今回は手動で `18` まで書き換えても解けますが、慣れてくるとPythonなどのプログラムを使って「0から50まで一瞬で送信して確かめる（ブルートフォース攻撃）」といった手法も使えるようになります！

#### 🎯 答え合わせ

**Flag:** `picoCTF{3v3ry1_l0v3s_c00k13s_bb3b3535}`

---

## 📅 第3回のまとめ

* **開発者ツール（F12）** はWeb解析の基本かつ最強のツール！
* **ソースコード（HTML/CSS/JS）** に機密情報（フラグ）が残っていることが…要チェック！
* **Javascript（JS）** のプログラムは簡単に読めるので、機密情報（フラグ）のヒントが得られることも…。大事なことは書かない！
* **Cookie** は自分で自由に書き換えられるため、機密情報（フラグ）が漏れる原因となる。サーバー側で厳重なチェックが必要。

<https://learn.cylabacademy.org/library/132>

ページの背景色を赤や青に変えるボタンがあるシンプルなサイトです。普通にボタンを押してもフラグは表示されません。
* **ここが学べる！【HTTPリクエストメソッド（GET / POST / HEAD）】**
ブラウザがサーバーにデータを要求する際、裏側では「GET（ちょうだい）」や「POST（送るよ）」といった命令を送っています。通信を「HEAD（ヘッダーだけちょうだい）」という別の命令に変えて送信することで、レスポンスの隠しデータ（ヘッダー情報）からフラグを取得します。
